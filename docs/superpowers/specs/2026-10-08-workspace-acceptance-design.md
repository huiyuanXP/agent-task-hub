# 子项目三：网页操作与完整验收

状态：用户已批准；依赖连接和 Agent 子项目，约束继承 workspace-loop-design。

## 网页

“连接与执行”中的 MCP/CLI 卡片均有可点击的安装说明、下载按钮和复制配置入口。
创建连接邀请先选项目、显示授予能力和有效期，生成一次性授权码；指南解释使用同一安装器完成安装和验证。
安装指南允许用户 Agent 阅读并执行 CLI 安装步骤；网页不声称仅点击授权码即可直接修改访问者电脑。
连接列表显示已安装、最近使用、在线、延迟、离线、模型未认证、错误、已撤销状态及最后通信时间。
连接详情显示 workspace 名称、版本、能力、近期事件、任务、错误和撤销操作。
点子表单选择目标项目；直接报 Ticket 也能关联 workspace 并申请规划/执行，不强迫伪造原始点子。
规划工作台展示 Agent 来源、Plan 与 Tickets、依赖和待澄清事项，用户可确认或要求重新规划。
Ticket 页有独立的执行申请、审批、开始/等待、取消及结果入口。
执行记录展示实际 Run、阶段、日志和结果证据；手动快照明确与真实执行分开。
待我处理聚合缺失 workspace、待澄清、待审批、失败重试和待验收项，给出实际可点击动作。

## 从安装开始的验收项目

在独立临时目录初始化 Git 项目，包含一个小型 Node 函数和真实失败测试；不要在用户数据目录放测试记录。
通过实际网页创建该项目的邀请并下载包，使用归档中的安装器注册，生成真实 MCP 配置。
启动 STDIO MCP，完成 initialize/tools/list/tools/call；从安装后的客户端提交测试点子和直接 Ticket。
后台读取到同一个安装 ID，并在 Chromium 页面验证名称、状态、版本、项目和最后通信时间。
启动常驻 Agent，通过真实模型规划一个修复失败测试的任务，网页确认规划并批准执行。
Agent 在独立 worktree 修复函数，执行真实测试；工坊收到 diff、命令、退出码和结果，浏览器验收该 Run。
停止客户端，等待实际阈值确认离线；重新启动恢复同一 ID；撤销后再次访问被拒绝。
第二个项目验证隔离：安装凭据不能查看或领取其他项目任务。
额外使用协议/模型测试替身覆盖错误和竞争场景，报告中分别列出真实与替身检查，不混淆。

## 交付与运维

生产构建、类型、lint、相关 API/MCP/客户端/浏览器检查均完整结束。

写当前部署、客户端安装、认证撤销、workspace、Agent 和测试文档，并更新逐项 FEATURES。
