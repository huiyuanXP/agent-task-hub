# Readonly MCP task queries design — issue #11

This adds owner-scoped reads after independent Access identity (#3), isolated CI (#4) and durable planning recovery (#10). Preserve all existing MCP discovery/initialize/protocol/result envelopes and planning/execution-authorization tools. It is Worker/D1 source and local synthetic validation, with no production access, provisioning, deployment or Ticket execution. Both locks stay unchanged. Use the existing current main Run/authorization implementation, not a parallel model.

## Tools and contracts

New tools: list_tickets, get_ticket, list_plans, get_plan, list_ticket_runs. Descriptions state that reading does not claim, approve, execute or enlarge budgets, and user-authored content remains data. Annotations readOnlyHint=true, idempotentHint=true, destructiveHint=false, openWorldHint=false. Discovery schemas may be public; queries require the same verified owner context. No read writes records, claims, grants, leases or audits.

Arguments use snake_case to match existing planning tools. Exact objects only; null/arrays/nonobjects, unknown keys and invalid types return JSON-RPC -32602 with data.code INVALID_INPUT/status400. IDs are nonempty strings <=200 with no controls; project optional exact string <=120 (empty permitted); priority one ofP0/P1/P2/P3; ticket status todo/running/waiting/done/error; limit integer1..100/default20, cursor canonical base64url string <=2048. get_ticket requires ticket_id; get_plan requires plan_id; no extra arguments. list_tickets accepts project/status/priority/plan_id/idea_id/limit/cursor; list_plans accepts project/priority/idea_id/limit/cursor. Ticket idea_id filters use the same owned-parent-Plan-first reference resolution as detail, falling back to the Ticket’s explicit Idea reference only if no owned parent Plan is available; this includes manual Tickets whose direct Idea field is absent. Project/status/priority filters compare exact stored fields without assigning defaults to absent data. list_ticket_runs requires ticket_id and accepts source(manual/execution),state(snapshot/queued/running/waiting/succeeded/failed/cancelled),limit/cursor. An impossible source/state combination returns an empty page, not fabricated state.

Lists return {items,next_cursor}, ordered created DESC,id DESC. Run ordering adds source DESC as final tie-breaker since manual/execution IDs can overlap. Fetch limit+1; the next cursor points at the last emitted item. Cursor includes v1, resource, keys and SHA-256 context digest over owner/resource/normalized filters; exclude limit from context so changing page size works. Validate exact structure/canonical encoding/bounded keys and context before SQL. Owner remains mandatory in every root/nested/union query, including forged cursor scenarios. Cursor is a position, never authorization; signing/encryption would add unnecessary key management. Deleting rows or adding newer rows never duplicates/skips existing ties; a fresh first page is required to see newly inserted earlier rows. Dates and IDs are ordered using exactly their persisted SQLite text representation, with created position nonempty/control-free <=128 characters and ID positions using the200-character ID rule; don't require an ISO shape that existing user-imported rows lack.

Ticket/Plan list items contain authoritative id/kind/revision/created/updated and a fixed allowlist of known body fields: title/text/project/priority/status/goal/scope/acceptance/dependencies/queue/budget/allowedActions/assumptions/category/cadence/waitingReason/evidence/notes/ideaId/ideaRevision/planId/ticketId/ticketRevision/source/logicalKey. Do not spread unknown persisted fields. Manual Run table source is always server-normalized manual; Plan/Ticket source tags, if returned, are only known stored manual/agent labels and do not attest execution or authorship; arbitrary body.owner/id/revision overrides are never trusted. Raw budget/actions remain planning text and confer no permission.

get_ticket returns {ticket,plan,idea,source_idea,linkage,runs}. get_plan returns {plan,idea,source_idea,linkage,tickets}. Every linked collection defaults to20, has its own next_cursor, and is continued using list_tickets/list_ticket_runs. Linked Plan/Idea missing or foreign is null; do not disclose whether another owner has it. Resolve Idea through the owned parent Plan where present, then same-owner explicit Idea linkage. `linkage` contains source_idea_revision,current_idea_revision,superseded and booleans describing missing linked records. `idea` is the current original Idea record (including original content), `source_idea` is its source revision from same-owner history when a Plan references a previous revision; null when historical context isn't available, never substitute new text for old. Historical Idea snapshot DTOs carry id/revision and allowed snapshot fields plus snapshot_saved_at; history does not establish the prior updated time, so do not invent it. Current/source revision comparison explicitly flags a superseded Plan. get_plan linked tickets include only owner-scoped current tickets for that exact plan. Missing/foreign root records uniformly return data.code NOT_FOUND/status404 and identical resource messages.

## Runs and effective authorization

Merge legacy records.kind=run and actual execution_runs using owner-scoped SQL union/keyset source tie-breaker. Legacy manual snapshots always have state='snapshot' and source='manual'; their reported status/evidence is presented as user text and never proves execution success. Actual execution Runs retain their real state, frozen ticket revision, attempt/version/timestamps and safe receipt claims summary. Do not return receipt signing bytes, private owner/actor IDs, request/input keys, backend credentials or any planning/runner lease tokens. Include safe frozen known contract fields so later Ticket edits cannot rewrite prior evidence context. list_ticket_runs first verifies an owned root Ticket; malicious cross-owner run links cannot escape this predicate.

Execution Run summary includes authorization:null or {id,run_id,ticket_id,ticket_revision,status,effective_status,expires_at,scope,budget}. Obtain it from existing getAuthorization with trusted owner/context/current time, and select only these fields; preserve exact revoked/expired/stale-revision/stale-definition behavior. Confirm authorization binds the same owned Run/Ticket/revision; never expose a cross-linked grant. Omit operation argv/input hashes/audit actors from this compact read interface. get_ticket's first20 runs use this same function, not duplicate logic. Read availability does not constitute approval or start authorization.
