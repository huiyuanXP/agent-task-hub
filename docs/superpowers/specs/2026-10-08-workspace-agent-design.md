# 子项目二：真实规划和开发 Agent

状态：用户已批准；依赖连接子项目，约束继承 workspace-loop-design。

## 规划

常驻客户端拉取本项目 queued 规划任务，使用既有领取 token、修订绑定、10 分钟租约和原子回写语义。
默认每 5 秒检查；本机每个客户端同时只处理一个模型任务；项目或账户不匹配的任务永不领取。
规划调用本机已登录的 Codex CLI，使用 read-only sandbox 与严格 JSON Schema 返回 Plan/Tickets。
点子原文作为数据传入，不把点子内的指令升级为安装、权限或宿主配置指令。
调用期限小于规划租约；租约到期或点子修订变化时终止并放弃旧结果，使用既有恢复机制重新规划。
计划返回可执行任务边界、验收标准和依赖；缺少目标仓库或必要信息时回写明确的待澄清原因。
缺少登录、模型不可用、输出无效及限流均有真实错误状态；不能用固定模板冒充模型成功。

## 开发执行与原有协议

评审并适配 PR #39 的授权、Run 绑定、租约代次和消费者恢复语义到当前 SQLite/账户；不拉回旧部署和旧身份依赖。
保留默认 Docker 验证操作和签名证据边界；新增独立的本机开发操作类型、权限描述与预算，不复用 30 秒 validator 假装执行开发。
owner 批准时固定 Ticket 修订、workspace/仓库标识、允许操作、执行方式、期限和结果要求。
客户端仅领取本项目已批准的 Run；owner 的审批/撤销工具不授予执行客户端。
一个 Ticket 同时只有一个有效开发执行租约；任务依赖未完成时明确等待，不直接越过依赖执行。
本机 Agent 的开发工作在指定仓库新 Git worktree 中进行，保留主工作区和已有改动。
调用 Codex CLI 的 workspace-write sandbox，并显式配置本次 MCP 服务；保留模型认证在本机，排除未批准的其他 MCP 配置。
开发操作起始不自动 push、合并远端 PR 或发布；批准范围包含这些操作时才开放对应能力。
超时、撤销、丢失租约和用户取消结束受管进程组；确认结束后释放运行占用。
中断后不得凭新代次重复启动仍然存活的进程；通过本机 journal/进程身份和服务端状态先对账。

## 进度和证据

持久化按 Run 排序的事件、游标、阶段、时间和脱敏消息；连接恢复可以从游标续读。
阶段至少包括领取、准备 workspace、Agent 工作、检查、等待、交付、失败和取消。
收集实际 worktree diff、修改文件、工具命令与退出码、测试输出和 Agent 结构化总结。
“Agent 说完成”只是候选结果，真实测试检查与差异证据满足后才交付待验收。
客户端签名结果必须绑定客户端、Run、Ticket 修订、许可和租约代次；网页显示结果来源是本机 Agent。
用户验收结果单独记录；返工创建明确的新尝试，不覆盖前一执行证据。

## 自举与独立验收

注册点子工坊自己的 workspace，先跑一个明确批准的小型开发 Ticket；将结果通过网页展示、验收，再有序更新本地预览。
现有两个用户点子首先作为规划输入，实际 PR 操作按新规划中审批范围执行，不直接批量合并。
测试覆盖双消费者竞争、自然超时、修改修订、撤销、重复报告、进程中断和租约丢失，防止重复执行。
需要一次真实模型调用和实际代码变更/测试结果；缺少模型登录时本子项目的真实闭环验收保持未完成。
