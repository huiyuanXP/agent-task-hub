# 点子、Plan、Ticket 详情页信息结构

本文说明已实现的详情页结构、字段映射与阅读/编辑合同。页面名称暂用「点子」「计划（Plan）」「任务（Ticket）」，保留 `idea`、`plan`、`ticket` 数据类型；中文名称与分组顺序供后续体验确认。功能现状见 [FEATURES.md](FEATURES.md)，本页与 `components/record-details/record-details.tsx` 的当前实现对应。

## 来源与展示约定

- [app/page.tsx](../app/page.tsx)：`empty`、`createPlan`、`createTicket` 给出初始值与继承关系，详情表单和点子、Plan、Ticket 卡片给出可见字段与动作。
- [lib/types.ts](../lib/types.ts)：`RecordBody`、`Row`、`PlanningMetadata` 给出记录及规划状态的字段合同。
- [components/planning-status.tsx](../components/planning-status.tsx)：`PlanningStatus` 与 `planningControls` 给出规划进度、原因、错误和按钮可用条件。
- [app/api/records/route.ts](../app/api/records/route.ts)：保存、修订冲突、等待原因、完成证据和手工执行快照的约束。
- [lib/connectors/planning.mts](../lib/connectors/planning.mts)：Agent 回写 Plan/Tickets 的来源、关联与默认值；[PLANNING.md](PLANNING.md) 和 [EXECUTION.md](EXECUTION.md) 描述规划与执行合同。

下表「默认展示」指详情打开即可看到；「折叠展示」指有标题和展开入口的补充分组；「编辑位置」明确可写控件所在分组。非空内容的判定为去掉首尾空白后仍有文字。折叠分组的摘要保留提示；默认展示的异常与等待信息随刷新更新。

记录字段来自 `/api/records`，规划元数据来自 `/api/planning` 或点子记录的 `planning`。真实开发 Run 与固定 Docker Run 使用各自的执行接口，说明见 [EXECUTION.md](EXECUTION.md)。只读的来源、版本、规划元数据与执行结果由接口提供。

| --- | --- | --- | --- |

| 标题 `title` | 三类详情表单；创建时为空或继承来源标题 | 「用一句话说明这条记录讲什么。」 | 默认展示；页头标题编辑，必填，最多 250 字。 |
| 项目 `project` | 三类详情表单；默认「通用」，手工拆分继承来源项目 | 「这条记录属于哪个项目。」 | 默认展示；页头基本信息编辑。 |
| 优先级 `priority` | 三类详情表单；默认 P2，手工拆分继承来源优先级 | 「表示处理的紧迫程度：P0 紧急、P1 重要、P2 常规、P3 有空再做。」 | 默认展示；页头基本信息选择。 |
| 标识 `id`、修订 `revision` | `Row`；详情页头显示修订，Ticket 卡片显示短标识 | 「标识定位记录，修订标明此次保存对应的内容版本。」 | 修订默认展示；完整标识折叠展示于「来源与历史」，只读；新建显示 NEW。 |
| 时间 `created`、`updated` | `Row`；点子卡片展示创建日期 | 「创建时间说明首次记录时间，更新时间说明最近保存时间。」 | 折叠展示于「来源与历史」，只读。 |
| 错误 `error` | 页面状态；接口读取、规划请求及保存错误均写入，表单外有 `role="alert"` | 「说明本次请求实际失败的原因，保存失败时保留输入内容。」 | 默认展示于页头反馈区或保存按钮上方，保留 `role="alert"`。 |
| 保存进度 `saving`、成功提示 `notice` | 页面状态；按钮及全局反馈 | 「保存中显示操作进度，成功后显示已保存到本地。」 | 默认展示；保存中依照现有条件禁用操作。 |

## 点子：原文与规划进度

默认阅读顺序：页头 → 原文 → 当前修订的规划进度与操作 → 关联结果 → 来源信息。

| 字段 / 信息 | 来源与现有位置 | 用途与一句中文解释 | 展示与编辑位置 |
| --- | --- | --- | --- |
| 原始内容 `text` | 点子详情表单；快速收集保存输入原文 | 「保留最初的想法、背景和上下文，供规划理解需求。」 | 默认展示全文；「原文」多行编辑。 |
| 规划状态 `planningStatus`、`planning.status` | 点子卡片；优先取匹配 `idea_id` 和 `idea_revision` 的 job，随后取 `planning`，`planned` 对应 `done` | 「展示当前点子修订从尚未规划、排队、处理中到结果保存的进度。」 | 默认展示于「规划进度」；只读，复用现有状态推导。 |
| 投递状态 `planningDelivery`、`planning.delivery` | 点子卡片 `PlanningStatus` | 「说明请求是否排队、等待项目 Agent、已经送达或投递失败。」 | 默认展示于「规划进度」；只读，沿用现有文案条件。 |
| 等待 / 恢复原因 `recovery_reason`、`targets[].reason` | `PlanningStatus`；原因去重后合并显示 | 「说明为什么正在等待、重试或需要恢复。」 | 非空时默认展示于进度下方；只读。 |
| Agent 错误 `planner_error` | `PlanningStatus`；Agent 回写实际错误 | 「说明 Agent 规划失败的实际原因。」 | 非空时默认展示全文于「规划进度」，只读。 |
| 租约 `lease_expires` | `PlanningStatus`；处理中显示到期时间与剩余秒数 | 「表示 Agent 本次领取规划任务的有效期限。」 | 折叠展示于「规划详情」；只读。 |
| 下次投递 `next_retry_at`、等待领取期限 `wake_deadline` | `PlanningStatus`；已接受投递时显示领取期限 | 「说明下一次投递时间，以及已送达请求等待 Agent 领取的期限。」 | 折叠展示于「规划详情」；只读。 |
| 手动重试冷却 `retry_after`、Agent 冷却 `planner_retry_at` | `PlanningStatus`；未来时间显示剩余秒数 | 「说明当前重试需要等待多久。」 | 冷却期间默认展示；只读。 |
| 重试资格 `retry_allowed` | `planningControls` | 「说明服务端提供的恢复资格，结合状态与冷却决定按钮是否可用。」 | 通过默认操作按钮体现；只读，由服务端裁定重试。 |
| 关联 Plan `planId`，Plan 的 `ideaId` / `ideaRevision`，Ticket 的 `planId` | 点子卡片按关联 Plan 及当前修订查找，统计 Tickets；`openPlan` 导航 | 「查看这条点子的规划结果及拆分任务。」 | 默认展示结果数量与入口；只读；未产生结果显示「尚未整理」。 |
| 规划诊断 `generation`、`recoveries`、`attempt_total`、`targets` | `PlanningMetadata`；属于接口元数据 | 「记录投递轮次、恢复次数和各接收目标的处理情况，供排查规划请求。」 | 折叠展示于「规划详情」；只读；目标标识、订阅标识、状态、次数、HTTP 状态和下次重试时间在此查看，原因同时保留在默认进度区。 |

点子详情表单的可写字段为标题、项目、优先级与原始内容。`notes` 和修订历史入口位于表单的 Plan/Ticket 分支；点子历史由保存接口保留，可在本结构的「来源与历史」中只读查看。`goal`、`scope` 等共用类型字段按各记录表单的实际用途映射。

## Plan：要解决的问题、完成标准、拆分任务

默认阅读顺序：页头 → 要解决的问题 → 完成标准 → 拆分任务 → 补充分组。

| 字段 / 信息 | 来源与现有位置 | 用途与一句中文解释 | 展示与编辑位置 |
| --- | --- | --- | --- |
| 目标 `goal` | Plan 详情表单；手工整理初值为点子原文或标题，Agent 提供规划目标 | 「说明希望解决什么问题、得到什么结果。」 | 默认展示；「要解决的问题」多行编辑。 |
| 范围与边界 `scope` | Plan 详情表单；手工填写或 Agent 规划输出 | 「明确这份计划覆盖的工作和边界。」 | 默认展示；「要解决的问题」多行编辑。 |
| 验收标准 `acceptance` | Plan 详情表单；手工填写或 Agent 规划输出 | 「列出可以检查的完成条件。」 | 默认展示；「完成标准」多行编辑。 |
| 关联 Tickets | 已保存 Plan 详情的 `tickets.filter(t => t.planId === draft.id)`；逐项标题与状态 | 「把计划拆成可以分别跟进的任务。」 | 默认展示于「拆分任务」；点击标题进入 Ticket 阅读视图；空列表显示「尚未拆分 Ticket」，新建 Plan 保存后建立关联。 |
| 来源点子 `ideaId`、`ideaRevision` 与原文 | 详情折叠原文；Plan 卡片显示来源修订与当前点子的比较 | 「说明计划依据哪一版点子形成，便于核对当前需求。」 | 来源修订是否匹配默认展示；原文、完整标识折叠展示于「来源与历史」，只读；缺失来源显示「来源点子不可用」，缺失修订显示「来源修订未记录」。 |
| 生成来源 `source` | Agent 回写 `source=agent`；属于记录元数据 | 「说明这份计划由哪种方式生成。」 | 折叠展示于「来源与历史」，只读，按接口实际返回值展示。 |
| 依赖 `dependencies` | Plan 详情表单；文字输入 | 「记录推进计划前需要完成的任务或满足的外部条件。」 | 折叠展示并在「依赖与假设」编辑；非空时主区默认显示「有依赖」及首条非空行摘要和展开入口。 |
| 假设 `assumptions` | Plan 详情表单；文字输入或 Agent 输出 | 「记录方案成立的前提，以及仍需确认的问题。」 | 折叠展示并在「依赖与假设」多行编辑；非空时主区默认显示「有待确认前提」及首条非空行摘要和展开入口。 |
| 允许的操作 `allowedActions` | Plan 详情表单；自由文字，手工拆分 Ticket 时继承 | 「记录约定的操作范围，实际执行权限以独立审批结果为准。」 | 折叠展示并在「执行约定」多行编辑；保留字段说明。 |
| 预算 / 限额 `budget` | Plan 详情表单；自由文字，手工拆分 Ticket 时继承 | 「记录预期投入或限额，实际资源约束以对应执行申请的有效预算为准。」 | 折叠展示并在「执行约定」编辑；保留字段说明。 |
| 补充说明 `notes` | Plan 详情表单；文字输入 | 「记录帮助理解计划的补充背景。」 | 折叠展示并在「补充说明」多行编辑。 |
| 修订历史 `history` | 按 `recordId` 关联历史；`previousRevision`、`created`、`snapshot.title`、`snapshot.goal || snapshot.text` | 「查看每次修改前保存的版本及当时内容。」 | 折叠展示于「来源与历史」，只读，保留现有历史摘要。 |

## Ticket：做什么、怎样算完成、当前进度

默认阅读顺序：页头 → 做什么 → 怎样算完成 → 当前进度 → 补充分组。

| 字段 / 信息 | 来源与现有位置 | 用途与一句中文解释 | 展示与编辑位置 |
| --- | --- | --- | --- |
| 目标 `goal` | Ticket 详情表单；手工从 Plan 继承或 Agent 输出 | 「说明完成这项任务要达到的结果。」 | 默认展示；「做什么」多行编辑。 |
| 范围与边界 `scope` | Ticket 详情表单；手工从 Plan 继承或 Agent 输出 | 「明确这次任务涉及的工作和边界。」 | 默认展示；「做什么」多行编辑。 |
| 验收标准 `acceptance` | Ticket 详情表单；手工从 Plan 继承或 Agent 输出 | 「列出检查这项任务完成情况的条件。」 | 默认展示；「怎样算完成」多行编辑。 |
| 验收证据 `evidence` | Ticket 详情表单；实际结果、测试输出或交付链接 | 「提供支持完成结论的实际结果，标记完成时必须填写。」 | 默认展示；「怎样算完成」多行编辑，`status=done` 时明确必填。 |
| 状态 `status` | Ticket 详情选择；初值 `todo` | 「记录任务的跟进进度，真实执行进度由对应 Run 提供。」 | 默认展示；「当前进度」选择待开始、进行中、等待中、已完成或异常。 |
| 等待原因 `waitingReason` | Ticket 详情在 `status=waiting` 时显示；卡片显示等待标签 | 「说明当前需要澄清、授权、验收、外部条件或恢复确认。」 | 等待时默认展示；「当前进度」必选，保持五种原因值。 |
| 真实执行进度 / 错误 | `DevelopmentPanel`、`AuthorizationPanel` 及执行记录；来源是执行接口 | 「展示已批准执行的实际进度和失败原因。」 | 有关联 Run 时在「当前进度」默认显示状态、非空真实错误与执行详情入口；完整日志、diff、收据在执行详情查看。 |
| 依赖 `dependencies` | Ticket 详情表单；文字输入或 Agent 输出 | 「记录开始或完成任务前依赖的 Ticket 或外部条件。」 | 折叠展示并在「依赖与假设」编辑；非空时主区默认显示「有依赖」及首条非空行摘要和展开入口。 |
| 假设 `assumptions` | Ticket 详情表单；文字输入或 Agent 输出 | 「记录执行方案依赖的前提，以及需要确认的问题。」 | 折叠展示并在「依赖与假设」多行编辑；非空时主区默认显示「有待确认前提」及首条非空行摘要和展开入口。 |
| 允许的操作 `allowedActions` | Ticket 详情表单；手工拆分继承 Plan 的文字 | 「记录约定的操作范围，实际执行权限以独立审批结果为准。」 | 折叠展示并在「执行约定」多行编辑；说明与 Plan 一致。 |
| 预算 / 限额 `budget` | Ticket 详情表单；手工拆分继承 Plan 的文字 | 「记录预期投入或限额，实际资源约束以对应执行申请的有效预算为准。」 | 折叠展示并在「执行约定」编辑；说明与 Plan 一致。 |
| 执行队列 `queue` | Ticket 详情输入；初值 `default` | 「记录任务的队列名称，实际领取顺序以执行接口为准。」 | 折叠展示并在「任务设置」编辑。 |
| 业务分类 `category` | Ticket 详情选择；初值 `general` | 「为任务标注业务领域：通用或求职。」 | 折叠展示并在「任务设置」选择 `general` / `recruitment`。 |
| 执行类型 `cadence` | Ticket 详情选择；初值 `one_off` | 「标注一次性或周期性意图，周期性调度尚待实现。」 | 折叠展示并在「任务设置」选择；周期性选项保留「周期性（尚未调度）」完整提示。 |
| 关联 Plan `planId`、来源点子 `ideaId` 与原文 | 手工拆分绑定 Plan 和点子；详情折叠原文，关联由记录保存 | 「追溯任务来自哪份计划和点子。」 | 关联摘要与来源入口默认展示；完整标识及原文折叠展示于「来源与历史」，只读；独立 Ticket 显示「独立任务」。 |
| 来源 `source`、逻辑标识 `logicalKey`、来源修订 `ideaRevision` | `RecordBody` 可携带的来源元数据；Agent 回写 `source=agent`、稳定逻辑 key | 「来源说明生成方式，逻辑标识帮助关联同一规划中的任务，来源修订标明依据的点子版本。」 | 折叠展示于「来源与历史」，只读；仅按接口实际返回值展示，缺失修订显示「来源修订未记录」。 |
| 补充说明 `notes` | Ticket 详情表单；文字输入 | 「记录执行和协作所需的补充背景。」 | 折叠展示并在「补充说明」多行编辑。 |
| 修订历史 `history` | 与 Plan 相同的历史关联及摘要字段 | 「查看每次修改前保存的任务版本及当时内容。」 | 折叠展示于「来源与历史」，只读。 |

## 动作映射

表内同时覆盖详情表单动作及与详情关联的现有卡片动作，实施时按记录是否已经保存和接口状态显示可用性。

| 记录 | 现有动作与来源 | 默认位置与行为 |
| --- | --- | --- |
| 三类 | 关闭按钮、点击遮罩、取消；`RecordDetails` 的关闭与草稿确认 | 页头关闭、页尾取消；保存中禁用关闭、取消及遮罩关闭，依照现有条件处理。 |
| 三类 | 保存到本地；`RecordDetails` → `save` → `POST /api/records` | 仅编辑状态在页尾展示；成功关闭详情并提示，失败保留输入与可见错误；已有记录携带 `revision` 保存。 |
| 点子 | 请求 Agent / 重试规划；卡片 `requestPlan` | 「规划进度」默认展示；已保存记录用 `POST /api/planning` 请求，沿用 `planningControls` 的租约、冷却、投递等待和恢复资格判断。新建点子先保存，保存接口持久创建当前修订规划任务。 |
| 点子 | 查看结果及 Plan / Ticket 数量入口；`openPlan` | 「关联结果」默认展示；规划完成时主按钮为「查看结果」，结果入口按关联数量启用，直接打开关联 Plan 或筛选规划工作台。 |
| 点子 | 手工整理；`createPlan` | 「关联结果」默认展示；创建 Plan 草稿，继承标题、项目、优先级及点子标识/修订，以原文或标题初始化目标。 |
| Plan | 点击关联 Ticket；详情按钮 `setDraft({...t})` | 「拆分任务」默认展示标题和状态，点击进入对应 Ticket 阅读视图。 |
| Plan | 查看 Tickets；卡片设置看板视图和 Plan 标识查询 | 「拆分任务」默认展示列表入口；按 Plan 标识查看关联任务。 |
| Plan | 拆分 Ticket；卡片 `createTicket(plan)` | 已保存 Plan 的「拆分任务」默认展示；继承标题、项目、优先级、目标、范围、验收及填写的预算/允许操作，绑定 Plan 与点子。依赖、假设、分类、队列和执行类型使用新 Ticket 初值。 |

## 可见性与语义合同

- 依赖和假设各自非空时，在主区显示对应提示、首条非空行摘要及直达展开入口；编辑时仍可从折叠标题添加内容。
- 开发执行会按其接口规则检查依赖，识别同项目任务标识或同 Plan 的逻辑标识；未满足或待澄清的依赖仍显示在主区，具体等待原因由执行接口提供。
- 规划等待/恢复原因、Agent 实际错误、Ticket 等待原因、关联执行的实际错误与保存错误均位于默认可见区域；完整日志和诊断保留展开入口。
- `goal` 描述期望结果，`scope` 描述工作边界，`acceptance` 描述检查条件，`evidence` 提供实际完成依据；填写验收标准和提供完成证据各有用途。
- `allowedActions` 和 `budget` 是填写的约定；有效执行授权来自独立审批，并绑定具体 Ticket 修订、执行方式、范围和期限。开发执行与固定 Docker 操作各自按 [EXECUTION.md](EXECUTION.md) 中的合同启动；固定操作使用登记操作、有效资源预算及签名后端。
- 手动选择 Ticket 状态表示跟进状态；真实 Run 的启动、进度和结果由执行接口提供。记录已有执行保存已有执行的手工快照。
- `priority`、`queue` 和 `category` 作为任务信息展示；`cadence=recurring` 展示「周期性（尚未调度）」。后台规划投递与租约维护按 [PLANNING.md](PLANNING.md) 运行，周期性任务调度作为独立能力待实现。
- 保存点子创建当前修订的规划任务；重新规划保留已有 Plan/Tickets 与执行证据，各修订的执行仍使用其独立有效授权。

## 阅读、编辑与返回

- 已保存记录默认展示只读全文；新建记录直接进入编辑，保存始终使用编辑开始时冻结的记录 ID 与修订。
- 折叠区域不会卸载字段或清空草稿，取消编辑恢复编辑开始时的内容。
- 有修改时关闭、返回或跟随关联入口会要求选择保存后继续、放弃修改或继续编辑，保存失败与 409 冲突保留草稿和可见错误。
- 弹窗限制 Tab 焦点，Escape 使用相同草稿确认；关闭恢复列表入口焦点，关联任务返回保留原计划的滚动位置和入口焦点。
- 关联入口不改写项目、搜索和状态筛选，不写入业务数据；手工整理、拆分任务和记录已有执行在阅读状态提供，编辑时先保存或取消。
- Plan 的任务列表显示完整标题、当前手工状态和已有目标，点子结果标注当前或旧来源修订，缺失关联记录显示真实空态。
- 查看、保存文字与手工执行快照不启动开发、不批准执行，也不使填写的预算和操作约定成为有效授权；实际执行沿用独立面板合同。
- 保存期间禁用详情字段，会话失效或退出清除详情、草稿和未保存确认。
